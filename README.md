# SAHITI.EXE — The Developer's Multiverse

A developer portfolio you can play. Visitors walk a pixel-art night town as a top-down RPG character and discover
skills, projects, experience, achievements and contact details inside six buildings — or switch to a clean,
recruiter-friendly Portfolio Mode at any time.

Built with **Vue 3 · TypeScript · Vite · Tailwind CSS 4 · Phaser 3 · GSAP · Lucide**.

## Run it

```bash
npm install
npm run dev        # development server
npm run build      # type-check + production build into dist/
npm run preview    # serve the production build
```

The build uses relative asset paths (`base: './'`), so `dist/` can be dropped onto any static host
(GitHub Pages, Netlify, Vercel, S3 …) without extra configuration.

Direct link for recruiters: add `?mode=portfolio` to the URL to open Portfolio Mode without loading the game engine.

## Make it yours — everything lives in `src/data/`

| File | What it controls |
| --- | --- |
| `profile.ts` | Name, role, intro, interests, journey, **email / GitHub / LinkedIn / resume links** |
| `skills.ts` | Skill categories and the text shown when a technology is inspected |
| `projects.ts` | The five project stations (description, problem, technologies, contribution, links) |
| `experience.ts` | Career HQ timeline |
| `achievements.ts` | Badges and their unlock conditions |
| `quests.ts` | Locations, missions, inventory items and the secret messages |

Links left as `''` are never invented: in the game they show as "not configured", and in Portfolio Mode they are hidden.
To add a resume, put `resume.pdf` in `public/` and set `links.resume` to `'./resume.pdf'`.

**To review before publishing:** the project `description` / `problem` texts in `projects.ts` are drafts written from the
project titles alone, and `technologies` / `contribution` / links are empty.

## Controls

| Input | Action |
| --- | --- |
| `W A S D` / arrow keys | Move |
| `E` (or click a building) | Interact / enter |
| `Q` · `I` · `M` | Quest log · Inventory · Locations (fast travel) |
| `Esc` | Close window / pause |
| Touch | On-screen d-pad and interact button appear automatically |

## How it is put together

```
src/
  data/            content only — types + the files in the table above
  game/            Phaser side (no Vue imports)
    bridge.ts        typed event bus + shared state: the ONLY link between Phaser and Vue
    config/          world layout (tiles, buildings, NPCs, secrets) and controls
    art/             pixel art, authored in code and baked into spritesheets at load time
    scenes/          Boot → Loading (bakes textures) → Intro (title backdrop) → World
    entities/        Player, NPC, InteractiveBuilding
    systems/         Collision, XP, Quest, Achievement — pure, framework-free logic
  composables/     useGameProgress (saved progress), useGameUI (window state), useAudio, usePortfolioMode
  components/
    game/            HUD, dialogue, minimap, location panels, menus, secret terminal, touch controls
    portfolio/       Portfolio Mode sections
    shared/          mode switch, settings, avatar, badge
```

**Progress** is a single action log (`visit:lab`, `tech:testing/playwright`, `project:facegreet`, …) saved to
`localStorage`. XP is granted once per unique action, and missions, achievements and level are all derived from that
log — so there is nothing to farm and nothing to get out of sync. *Settings → Reset progress* clears it.

**Art** is generated by the functions in `src/game/art/` (see `art/index.ts` for the full texture list). Each entry
produces a spritesheet with a fixed frame size, so any of them can be replaced by a hand-drawn PNG of the same
dimensions without touching scene code.
